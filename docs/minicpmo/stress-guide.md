# 压力测试与瓶颈诊断：执行指导

固定主线：MiniCPM-o 4.5 + vLLM-Omni。**先统计工作量、测压力边界、定位瓶颈，再研究 Thinker PD。** Talker/Code2Wav 共卡干扰是独立候选方向。本页是压测的唯一详细矩阵，[总计划](plan.md)保留阶段关系；完成情况以[结果与证据](results.md)为准。表中实验均为待执行计划。

## 1. 实验分类与控制变量

| 类别 | 变化 | 要回答的问题 |
|---|---|---|
| 压力测试 | 并发、输入量、持续时长、到达节奏 | 稳定区、过载区及失败位置 |
| 瓶颈诊断 | 独立/共卡/分卡、执行时间线 | 为什么慢，谁在等待谁 |
| 配置对照 | 已有批处理、分块、缓存参数 | 排除不合理配置，建立调优基线 |
| 方法评估 | 普通 PD、分批 KV 传输、新调度 | 方法收益、代价与适用范围 |

四卡是可用资源预算，不要求第一轮用满。先测已验证两卡布局：Thinker 一卡，Talker/Code2Wav 共卡。三阶段各一卡、Thinker TP=2 等布局须先验证再测；TP 不是 PD。各布局独立扫描负载，不能将增卡收益归给策略。

| 控制项 | 必须满足 |
|---|---|
| 硬件 | 保存 GPU 数、UUID、型号、PCIe/NUMA 拓扑、实际传输路径、其他进程；不操作他人作业，不改全局驱动/CUDA |
| 软件 | 固定模型/引擎 revision、精度、后端、图优化、采样及参考音色；给予基线同等调优机会 |
| 到达 | 预生成输入时间表，真实媒体时钟；不因输出慢而主动降速。记录计划、发送开始/结束和阻塞；不能提前发送未来帧 |
| 历史 | 同组固定窗口策略；当前 basic high=8000/low=6000 是起点，不为高并发暗中缩短。记录实际清理与总 KV 预算 |
| 重复 | 分开冷启动、预热、正式测量、排空；正式条件至少三次，保留全部结果，轮换次序并报告样本数 |
| 内容 | 正式实验有多个不同内容/来源。官方短片或循环短片仅作预检、测量验证、机械长期稳定性，不代表独立用户或长视频理解 |
| 功能 | 检查输入丢弃、回答/音频完整性、打断、状态隔离与必要质量；不能靠少处理内容换速度 |
| 接入 | 使用现有网页/实验互斥，覆盖整个实验；仅监听 127.0.0.1，退出确认解锁 |

### 显存统计口径

Code2Wav 权重小，但需要逐请求参考 prompt 特征、Flow/HiFT 上下文状态、中间张量和图缓存。分别统计静态加载、池预留、活动状态和峰值；不能把整个进程占用都叫 KV。

官方两卡配置预算比例为 Thinker 0.90、Talker 0.55、Code2Wav 0.35。本项目已验证四会话两卡配置将 Talker 改为 0.25，其余按实际文件记录。这些是引擎预算参数，不是算力份额、历史窗口或所有分配的硬上限。池内回收通常不等于归还 CUDA 显存给另一个进程。

固定权重元素：Thinker 9,024,091,376（语言主干 8,189,195,264），Talker 347,696,290；Code2Wav 核心 Flow/HiFT 176,623,647，不含 ONNX 辅助模块。核心全 FP32 估算 0.706 GB/0.658 GiB；“约0.56GB”等口径须注明具体版本、模块和精度，不能与运行峰值混用。

## 2. Thinker 主线实验

P/D 暂不分卡，语音侧布局固定且监控下游积压，避免把背压归因于 Thinker 算得慢。

| ID | 明确对比什么 | 唯一主要变量 | 关键指标/判断 |
|---|---|---|---|
| T1 | 单会话倾听、短答、长答片段 | 输入/实际回答类型 | 新增输入位置、语言/控制输出、编码/P/D耗时及时间线、首文字 |
| T2 | 同布局 1/2/4 会话，容量门槛通过后细扫 | 活跃会话数 | 逐流实际到达/处理量、积压斜率、新鲜度、尾延迟、失败及公平性 |
| T3 | 短/中/近上限历史后，处理相同后续片段 | 有效历史/KV长度 | 后续计算、裁剪/重算、峰值显存；实际生成量单列，避免历史改变回答造成混淆 |
| T4 | 支持范围内低/默认/高视觉密度 | 采样密度、分辨率分别扫描 | 编码/P工作量、D受影响程度、实际输入位置；不任意加速音频 |
| T5 | 多会话集中/错峰回答；短/长答分别分组 | 回答触发时间 | 生成期间输入等待、P/D竞争、输出间隔；不假定模型必然按要求说话 |
| T6 | 新会话单独进入，与长历史背景会话共存 | 背景数量/历史 | 新用户首答、服务份额、饥饿 |
| T7 | 平稳到达与突发，之后恢复正常 | 会话加入突发、输入突发分别测 | 队列增长/消退、拒绝/超时、恢复时间；完整工作量一致 |
| T8 | 初/中/后期，及会话加入退出 | 时长 | KV/状态回收、显存、长期积压；至少三次实际窗口清理，未触发则不能验收回收 |

## 3. 语音候选线实验

先记录真实 Thinker→Talker 条件、Talker→Code2Wav codec 与元数据，再通过原模型路径回放；保留逐会话状态与音色。回放入口未实现前不以随机张量代替正式负载。完整验证保留官方播放 ACK/打断语义。

| ID/类别 | 明确对比什么 | 主要变量 | 关键指标 |
|---|---|---|---|
| S1 诊断 | Talker独立、W独立、完整共卡、完整分卡 | 竞争/布局 | 执行/排队、首音频、显存；独立测量尽量保留另一模块加载但不执行 |
| S2 压测 | 每种布局 1/2/4 会话后细扫 | 会话数 | 积压、首音频尾延迟、模拟播放缺口、错误 |
| S3 压测/诊断 | 相同完整工作量集中/错峰说话 | 各流相位 | 峰值队列、缓冲余量、逐流尾延迟 |
| S4 同预算 | 两张语音GPU各一套共卡副本 vs Talker/W各一卡 | 相同GPU预算的分工 | 相同延迟/连续性要求下的会话数、每GPU服务能力 |
| S5 配置 | 相同codec序列的小/默认/大块 | 支持的块大小 | 首音频、计算/提交次数、缓冲；检查尾块、左上下文及音频完整性 |
| S6 完整验证 | 接回Thinker的共卡/分卡及长期运行 | 布局/时长 | 端到端体验、Thinker受影响、状态回收与公平性 |

共卡一张与分卡两张只作诊断，资源效率用S4。一般GPU共卡干扰已有研究；候选差异是有生产消费依赖、受连续播放期限约束的语音链，不能提前认定新颖性。

## 4. 指标字典

| 层级 | 必采内容 | 起止与限制 |
|---|---|---|
| 输入 | session/event ID、源区间、可用/计划/发送开始结束、实际字节/帧 | 发成功不等于模型处理；客户端迟到/阻塞单列 |
| 工作量 | Thinker文字/图像/音频新增位置、语言/控制token；Talker条件token/特征形状字节；codec数量、音频秒数 | 不把帧、字符、不同token相加；累计prompt未核验前不当新增量 |
| 执行 | 编码/P/D控制/Talker/W的CPU区间及GPU执行区间 | wall time不能冒充kernel时间；重叠区间不能直接求和当关键路径 |
| 排队 | 各阶段等待、待处理源时间、最新已处理源时间、积压斜率 | 不用最新发送画面冒充新鲜度；丢弃/合并必须记录 |
| 文字 | 问题结束→首回答、输出间隔 | 倾听无回答不是TTFT；transcript不一定是Thinker原始token |
| 音频 | 回答触发→首音频、语音入口→首音频、逐块时间/时长/response ID | 无可靠触发关联时仅报response.created→首音频/相对会话时间，不伪造用户TTFT |
| 播放 | 逐回答模拟消费的缓冲余量、缺口次数/时长 | 起播缓冲0/100/300ms单列；回答间静默不算断音；模拟结果不是实际听感 |
| 容量 | 每会话有效KV、总池占用、裁剪/重算、各进程和整卡显存 | 单会话窗口与总池容量分开；OOM是容量失败，不是计算饱和 |
| 可靠性 | 逐流完成/拒绝/丢弃/超时、隔离、质量 | 独立session ID不能证明KV数值隔离 |

边运行边刷新JSONL，崩溃保留最后输入/输出时间。保存配置hash、媒体来源/hash、固定版本、冷/热状态、测量覆盖矩阵。缺失指标必须是 `null + 原因`，不可填0。GPU trace单独跑并估计插桩开销；统计型引擎指标先核验是否覆盖原生双工以及各stage。

压力到位需同时观察稳定区和过载区：持续积压、吞吐平台、期限违约或拒绝增加等。GPU利用率仅辅助。第5个被配置拒绝不是GPU饱和；客户端发送跟不上则标记未按计划施压。没有足够稳定观测区间不报最大容量。

## 5. 执行队列与验收

| 顺序 | 任务 | 完成门槛 |
|---|---|---|
| E0 | 资源/配置/指标预检 | 保存实际拓扑、占用、健康、版本；未知指标列缺口 |
| E1 | 全过程计时短回放，预热后单会话三次 | 每包输入与每块输出可追溯，失败也有部分日志；仅称测量验证 |
| E2 | 初步1/2/4会话扫描 | 每会话结果、真实到达、输出时序、资源记录齐；同短片不算正式多样性 |
| E3 | 600秒机械长会话 | 有界时长、崩溃可定位、记录有效历史；循环视频不算真实长视频能力 |
| E4 | 补齐逐阶段/逐会话token、KV、GPU trace | 含义与覆盖范围核验；不拿累计计数冒充全量观测 |
| E5 | 正式T1/T2/T3/T8，随后S1/S2/S3及其余矩阵 | 多内容、至少三次重复；单元180秒起，长期测试按窗口触发和稳定区间延长 |
| E6 | 普通PD→分批传输 | 先保证严格历史交接正确；固定资源语义，测通信、重叠、额外状态和负收益 |

每步归档通过/失败/缺失、原始证据、下一步。失败先健康检查和原因分析，不盲目重跑或越过依赖。3090用于机制与前期测量，H200+IB要重新验证容量、带宽、基线和收益。
