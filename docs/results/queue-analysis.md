## 可以支持的观察

- single 的 rate4：网关平均排队占发送后平均首文本等待的 79.1%。
- replicas 的 rate4：网关平均排队占发送后平均首文本等待的 91.3%。
- nccl 的 rate4：网关平均排队占发送后平均首文本等待的 89.4%。

旧配置的两 GPU 网关只允许 4 个活动请求；这提示首先检查接纳上限与引擎实际利用的关系。
不能仅据此断言 GPU 已饱和、传输是瓶颈，或简单提高上限一定更好；需要持续负载与接纳上限对照。

“其余首文本等待”= 客户端发送后首文本时间 − 网关排队 − P 服务往返。
该余项包含客户端/HTTP 开销、D 排队、输入处理及首个输出等，不能命名为纯 D prefill。
P 服务往返也不是纯 GPU prefill；可见回答阶段不是纯 GPU decode。
各阶段分位数不能相加。旧实验只有短时重复，不认定稳定容量或 PD 算法优劣。
