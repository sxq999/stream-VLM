# 官方视觉合并：完整片段工作量检查

本轮在相同两张 RTX 3090 上，沿用已核验的重复投影清理路径，仅切换官方 `batch_vision_feed`。同一段 188 秒音视频，两类负载、两个版本，共完成 752 单元。关闭开关版本逐单元匹配此前冻结参考。

| 负载 | 版本 | 单元 | 说话单元 | 语言 token 合计 | 语音 token 合计 | 波形样本数 | 最终 KV 长度 |
|---|---|---:|---:|---:|---:|---:|---:|
| listen | unbatched | 188 | 0 | 0 | 0 | 4512000 | 14922 |
| listen | batch | 188 | 0 | 0 | 0 | 4512000 | 14922 |
| talk | unbatched | 188 | 15 | 55 | 353 | 4515840 | 15017 |
| talk | batch | 188 | 21 | 76 | 498 | 4511040 | 15044 |

工作量门槛：**未通过**。逐单元工作量差异 118 处；文字或波形哈希变化 17 个单元。比较字段是交互状态、回合结束、语言／语音 token 数、波形样本数、KV 长度。

最早工作量差异：`talk` 第 71 单元。

根据运行前固定的门槛，本轮没有启动配对性能测量，不给出同工作量加速比。先前 16 单元短预检通过行为／计数检查，不能推广为完整 188 单元负载等价。118 处是出现工作量差异的单元数；前面生成不同会影响后面的 KV 长度，不能视为 118 个独立错误。

下一步若继续评估视觉输入合并的执行效率，应另立固定历史／固定 token 轨迹的计算对照：在相同前缀和输入下，测同一批模型计算的 GPU 完成时间，把自由生成长度的变化排除。这只能说明受控计算效率；若要报告自然交互端到端收益，还需同时评价生成行为和质量。

这是已有官方能力的基线核验，没有新增算法或 PD。数值路径改变可能影响后续采样；当前未隔离其全部因果来源。工作量变化不直接证明任务质量下降，工作量一致也不证明音质或语义等价。

61 项回归测试：60 项通过，1 项跳过。资源采样中没有观察到外来计算进程；原始记录、源码快照和哈希保存在私有归档。
