# 先定位瓶颈：输入等待、语言、语音 token 与波形

本实验先保持原生输入/输出顺序和模型权重，不实施 PD、主动切分或复制/重建策略。目的在于判断下一输入的等待发生在什么阶段，再决定改什么。

## 固定的执行放置

```text
GPU 0：视觉/音频编码 → 语言 P、D → 语音 token
GPU 1：波形 W
```

这里的 W 只指波形模型，不包括主卡上的语音 token 模型。语言 P/D 仍同卡。完整 PDW 需要另外的模型放置、KV 传输、显存预检与相同资源预算比较；不能把本实验称作 PDW 部署。

## 三项有边界的测量

1. **观察工具开销校准。**同一 76 单元前缀，关闭/启用计时交替执行两对，保持输出一致；属于最快回放，不能混进实时性能统计。
2. **188 单元实时回放，三次。**独立来源每秒提供一份真实音视频，不等待模型完成。在第 60/128 单元以文字注入官方问题，逐项核对已有冻结输出。记录输入到达、prefill 起止、语言状态提交、语音 token/波形起止和完整返回。
3. **固定状态成本微测。**从原生连续轨迹抓取真实视觉 embedding 与历史 KV，分别改变所用历史长度和输入 token 数。每次独立恢复 KV，在计时范围外传入；只测语言前向，不生成新答案。这是人为控制形状的成本实验，不是改变历史后仍保持质量的证明。

GPU event 不在每个计时点强制同步。其区间含流内空隙与主机提交等待，不是 kernel 时长之和；主机 API 边界也不是 GPU 完成时间。两种时钟分别保留，并记录时钟锚点的不确定区间。

## 从等待中能解释什么

把输入排队区间与前序单元的主机阶段区间相交，分为输入 API、语言生成/控制、语言之后的声学尾部和其他组织开销。各部分必须与观察到的排队时间对账，拒绝重叠重复统计。

“等待期间正在执行波形”是执行位置的证据，不等于删除波形就能省去同样时间。并行会改变资源竞争、声学状态及提交行为，仍要另做对照。

## 运行与产物

入口：[bottleneck_probe.py](../../scripts/venus/bottleneck_probe.py)；配置：[bottleneck-attribution.json](../../configs/venus/bottleneck-attribution.json)。参数沿用已有 Venus 实验的 `--reference`、`--model`、`--hf-home`、`--gpus`、`--state-module`、`--fastpath-module`、`--baseline-plan`、`--reference-results`，另给新的 `--out` 和上述 `--plan`。

需要先生成并核验 [单会话原生参考](single-session.md)。输入解析、采样、窗口和相关源码哈希必须匹配；失败后保留原目录，修改后另建运行目录。大权重、输出音频与原始实验目录不提交 Git。

分析入口：

```text
python scripts/venus/bottleneck_analysis.py <完整 campaign 目录> --out <新的分析目录>
```

输出包括原始单元记录、主机/GPU 流时间点、到达资格检查、逐单元等待归因、固定状态成本表、源码哈希和完成/失败记录。

## 当前结论边界

这是单会话、单视频、固定模型与设备上的诊断，不是多会话容量或通用压力极限。完整 PDW、主动切分、真实 KV 交接、复制与重建、其他芯片以及真实播放与任务质量，均需要独立实验。

三卡独立前置检查入口：[pdw_feasibility.py](../../scripts/venus/pdw_feasibility.py)。用 meta 构造语言副本时必须保持源参数及非持久位置编码缓冲区的 dtype，并复制普通 tensor 别名；数值门槛失败时即使没有 OOM，也不得视为正确交接。结果见[本轮汇总](results/bottleneck-attribution.md)。
