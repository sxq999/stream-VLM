# 流式 VLM 通用实验管线 v1：实施任务书

状态：任务设计完成，尚未实施。范围以本文件为准。历史 stream_baseline 实验原样保留，只复用数据和已验证的因果处理逻辑。

## 1. 交付目标与停止条件

交付可配置、可部署、可观测、可回放的流式 VLM 管线，用于后续模型性能分析、算子分析、内存/调度实验、提前计算和 PD 实验。实现现成后端的适配与标准实验接口；本期不提出新优化机制、不搜索最优参数、不进行模型训练/微调、不以速度提升或论文创新作为验收条件。

完成条件：下面所有“必须实测”项通过，统一命令能重现验收，能力矩阵、依赖锁定、部署说明、原始日志和验收报告齐备。满足后冻结 v1；不因发现性能问题而自行扩展优化任务。

## 2. 模型与后端边界

| 对象 | 本期交付 | 验收等级 |
|---|---|---|
| Qwen/Qwen3-VL-8B-Instruct | 原生参考适配、vLLM 服务、持续视频输入与多次文本查询 | 必须实测 |
| Qwen/Qwen3.5-9B | 原生参考适配、vLLM 服务；声明注意力 KV 与循环状态的后端能力 | 必须实测 |
| openbmb/MiniCPM-o-4_5 | 官方原生/官方 vLLM-Omni 路径；视频+音频持续输入、文本和音频输出 | 必须实测；不要求三个后端使用同一底层 API |
| Qwen3.8-Flash-Next 等大模型 | 模型注册配置、资源预检与能力声明接口 | 不下载/部署/跑分；部署留到后续硬件与量化任务 |
| 未核实的模型名，如 Qwen3.8-9B | 明确返回未注册/待核实 | 不自动替换成其他模型 |

正式安装前，逐项锁定精确模型 revision、引擎 commit/版本、PyTorch/CUDA/驱动兼容组合，并保存来源与配置。每套后端使用隔离环境或容器。保留现有环境；本期不升级共享服务器驱动。如果核心模型需要当前硬件无法支持的版本，先寻找官方支持的兼容组合；仍不可行则记录阻塞及明确剩余工作，不能将该项标为完成。

实施资源边界：按已知8×3090环境规划，先重新盘点再选择空闲GPU；本期同时占用最多4张，默认使用最少可运行数量。每个模型/后端最多验证两套有官方依据的依赖组合；超过此范围仍不能跑通时，交付复现证据与阻塞说明，不能无限更换版本或转入驱动/底层算子开发。GPU等待上限默认30分钟，可由运行配置明确修改；超时记录资源阻塞。阻塞报告表示工作尚未全部完成，不等于验收通过。

## 3. 统一管线结构

数据源/可重复回放 → 因果输入时钟 → 有界会话输入队列 → 模型适配器 → 执行后端 → 输出事件 → 观测与归档。

控制面独立管理模型、会话、资源分配、负载配置与运行生命周期。harness 发工作负载和记录证据；后端执行其自身批处理、KV/状态管理与调度。普通服务通过 HTTP/OpenAI-compatible 接口接入；全双工通过官方会话接口接入，不强制伪装成普通单轮 HTTP 请求。

### 统一接口

- `capabilities()`：声明支持的模态、持久状态、前缀缓存、增量 prefill、取消、音频输出、PD、状态导出/导入等；区分后端原生能力与管线已验证能力。
- `create_session(config)`、`append_input(event)`、`submit_query(query)`、`stream_output()`、`cancel(request_id)`、`close_session()`。
- 受能力限制的扩展接口：`prepare_media()`、`prefill_prefix()`、`export_state()`、`import_state()`。不支持时返回明确错误，不能静默重算后冒充复用或迁移。
- 状态句柄包含会话、模型 revision、精度、位置/模板版本、输入提交边界、状态版本。实际 tensor 布局由引擎管理；管线不自写通用 GDN/QSA KV 分配器。

### 会话语义

标准 VLM 默认使用“查询快照”：查询只看到到达时刻前的因果输入；生成期间新输入可以接收，但归属下一快照。若后端不能持久追加模型状态，允许完整前缀重放，但必须标为 `prefix_replay` 并计入全部计算；不能称作原生增量推理。

MiniCPM-o 的原生全双工模式独立声明，保留官方输入输出交错规则、turn/epoch 与取消语义。原生双工与查询快照的结果不混合成同一语义对照。

## 4. 数据与事件合同

输入事件必须包含：schema_version、session_id、event_id、source_seq、模态、源采集时间区间、源 PTS、完整载荷就绪时间、文件/缓冲区引用与哈希。查询包含 query_id、到达时间、evidence_cutoff 和提示词。评分答案单独存储，运行阶段不读取。

支持现有 timestamped JSONL 和本地视频/音频文件；提供可重复的实时速率与最快回放。v1 不集成物理摄像头、WebRTC、浏览器界面或外部业务系统。

必须支持可配置采样率、尺寸/像素上限、音频开关、查询计划、最大上下文、队列容量。严格保留小数时间边界；帧/音频不能越过 evidence_cutoff。模型要求的补齐、冻结回答尾部、重采样均记录。超过容量的行为可配置为显式拒绝或 drop-oldest，并逐项记录丢弃 ID；没有静默丢帧。

源时钟与运行时钟分开存储，单机统一 monotonic 时钟。跨主机事件保留各机时钟域，未经时钟校准不能相减作为端到端耗时。

## 5. 必须提供的部署模式

### 单设备测量配置（为后续端侧工作提供接口）

在一张 3090 上运行两种 Qwen 小模型的受限输入配置；独立记录加载、预处理、编码、prefill、decode、TTFT、生成间隔、显存和可获取的功耗。若显存不够，先缩短上下文/限制视觉输入并记录配置；本期不开发量化方案。此配置不能标为手机/嵌入式端侧验证。

### 同机 serving

提供 vLLM/vLLM-Omni 服务启动与停止、健康检查、请求路由、会话隔离、可配置请求到达率/并发、固定资源配置。使用引擎已有调度与内存管理，暴露参数并保存最终生效配置；不修改调度算法。

### Prefill–Decode 分离

使用官方现成连接器，在同一服务器的独立 GPU worker 上，先对 Qwen3-VL-8B 完成真实 prefill/decode 分离与状态传输。必须证明两个 worker 的角色、状态发送/接收和 decode 的依赖关系；两张 GPU、两个普通模型副本或 thinker/talker 分离不能替代此项。

v1 PD 使用查询快照；新帧在当前回答期间进入下一快照，不实现并发增量状态跨 P/D 的一致性新机制。PD 的模型/连接器/拓扑必须进入兼容矩阵。若官方组合不支持所需多模态状态传输，则该项未完成，记录问题后再确定兼容实现，不能用文本模型实验替代多模态验收。

### 多机排布

提供可指定 encoder/prefill/decode 角色、host、GPU、端口、连接器、路由的配置和启动模板；本期对已知单机环境实测。没有第二台机器时，多机仅标为配置与接口交付，不能标为已验证多机部署。跨机性能和网络调度优化不在本期。

## 6. 提前计算与分析入口

交付 `off / media_prepare / prefix_prefill` 的策略入口。必须实测 `off` 与提前媒体解码/编码准备；`prefix_prefill` 只在后端确实支持因果前缀追加/缓存复用时启用，验证边界、失效与真实复用计数，否则明确标为不支持。仅提供扩展点不等于已经实现该能力。

提前计算耗时、常驻内存、缓存命中/失效、未被查询使用的工作量必须入账。模板/位置/模型不兼容时拒绝复用。

提供一次独立 profiling 的标准命令，导出 CPU/GPU trace 和阶段边界，供后续算子优化。没有内部 hook 的阶段记录 unknown 或上层区间，不将墙钟时间冒充独占 kernel 时间。Profiling 与正常延迟测试分开执行。

## 7. 可执行实施顺序与产物

1. **环境预检与依赖锁定**：产出硬件清单、模型/引擎/连接器矩阵、空间预算和隔离环境锁文件。
2. **接口与因果数据层**：实现事件 schema、输入时钟、会话队列、能力检查、统一输出与取消/清理；用可控输入完成边界测试。
3. **三模型适配**：先 Qwen3-VL，再 Qwen3.5，最后 MiniCPM-o；逐项完成原生参考和目标服务路径的冒烟验证。
4. **部署与负载运行器**：单设备、同机服务、PD 及多机配置模板；实现统一 CLI、资源与端口隔离。
5. **提前计算/可观测性**：接入现成能力、记录开销与生效参数，完成独立 trace 导出。
6. **统一验收与冻结**：运行固定验收矩阵，生成逐项 pass/fail/unsupported/blocked 报告，打包代码、锁文件、配置、样例、日志、说明和校验清单。

建议目录：`src/{events,sources,sessions,adapters,backends,metrics}`、`configs/{models,deploy,workloads}`、`tests/`、`examples/`、`runs/`、`docs/`。不把历史数十个实验脚本全部搬入新实现。

CLI 合同（计划接口，当前尚无这些实现）：

```
python -m stream_pipeline doctor --config CONFIG
python -m stream_pipeline serve --config CONFIG
python -m stream_pipeline run --config CONFIG --out UNIQUE_RUN_DIR
python -m stream_pipeline profile --config CONFIG --out UNIQUE_TRACE_DIR
python -m stream_pipeline validate --suite configs/acceptance.yaml
```

每个运行目录必须含配置/源代码/模型/依赖身份、输入清单、输出与时间线、资源记录、失败原因和汇总。输出目录不可覆盖。CLI 配套提供 Linux 启动脚本及本地调用说明。

## 8. 有限验收矩阵

| 项目 | 固定验收用例 |
|---|---|
| 因果与接口 | 整数/小数截止、补齐、越界拒绝、会话隔离、队列溢出、取消、异常清理、错误能力组合 |
| 三个模型 | 每个原生参考完成一个短样例；每个目标服务后端完成60秒单会话、120秒双会话，多次查询；MiniCPM包含真实音频输入及非空音频输出 |
| 单设备 | 两个Qwen各一次单GPU受限配置，记录完整配置与显存；不要求最大上下文 |
| serving负载 | Qwen3-VL额外完成120秒四会话；不要求性能胜过参考或达到特定吞吐 |
| PD | Qwen3-VL完成五个固定短请求及一次60秒双会话；记录实际传输和完整响应，检查状态/会话不串用 |
| 提前准备 | 同一输入完成off/on各一次；检查因果输入边界一致、全部准备开销入账，提供复用/失效证据 |
| profiling | Qwen3-VL一次短trace，能打开并映射到会话/请求/阶段；不要求热点调优 |
| 重现 | 从锁定环境与配置重跑一个完整示例，生成相同结构且可审计的记录；不要求浮点执行跨后端逐token完全一致 |

正确性分层：事件、查询边界、状态身份必须严格一致；模型输出保存原文并按固定简单任务检查基本可用性。每个适配器至少通过一个已知答案的简单视觉任务；MiniCPM至少完成一次可听音频输出的人工/实际播放复核。不同模型/精度/后端的原文差异单独报告。PD与非PD在同模型/精度/输入下比较生成token与结束状态，任何差异都必须解释并通过明确的正确性检查，不能只以HTTP 200作为通过。

不采集完整真实用户对话，不接入外部付费评分服务。使用既有短视频、可控输入和合法可用的本地音频完成基础验收；不开展全量benchmark或新的质量研究。

## 9. 必须交付的能力矩阵

每个模型×后端×部署模式列出：可加载、视频输入、音频输入、文本/音频输出、会话持久性、实际状态类型、前缀复用、提前prefill、取消、PD、单机/多机验证等级，以及对应运行目录。未测试和不支持必须区分。

“支持上述”不等于所有模型都支持全部组合：三个核心模型的基本运行与明确要求的Qwen3-VL PD必须实测；混合模型PD、自定义GDN/QSA状态迁移、跨机实测、真端侧设备、所有组合的提前prefill属于声明能力/扩展接口或后续任务，不能夸大为本期已实现。

## 10. 明确不纳入本期

自研CUDA算子、量化/蒸馏/微调、学习型帧选择、缓存替换算法、新调度策略、新PD协议、混合状态迁移算法、最大吞吐搜索、论文实验、创新性审查、手机部署、物理播放/打断产品系统和可视化前端。

后续发现的问题进入问题清单，附复现命令、日志和建议；不自动开展优化。仅修复阻止本任务验收的功能、兼容性与正确性问题。
